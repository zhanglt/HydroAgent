# 总览与调度性能优化实施记录

日期：2026-11-18。对应[历史分析](performance-analysis.md)和[优化计划](performance-optimization-plan.md)。本记录描述当前代码与隔离验证，不代表已部署到用户的 3000/7860 服务。

## 1. 已实施的变更

### 后端读取与安全

- 当前传感器接口直接读取传感器摘要，不再调用完整分区证据收集；天气接口直接读取天气，不再收集传感器、计划和设置。这两个同步 I/O 接口改为 FastAPI 普通函数，由线程池调度；分区状态和手动控制入口也采用普通函数。
- 异步计划生成、执行与非流式聊天入口预先在线程池中获取天气，只传递地点字符串，不向天气线程传递数据库会话。后续证据收集复用缓存。未将所有现有同步业务处理改为异步，也未移除所有历史工具的直接天气调用。
- 天气缓存为 600 秒，传感器缓存仍为 5 秒；按地点合并正在进行的刷新。天气失败缓存 5 秒以限制连续重试；失败后释放并发等待者。采集时间在命中缓存时不更新。
- 天气返回 `status`、`collected_at` 和来源。首次失败为 `unavailable`，过期刷新失败为 `stale`，不生成模拟晴天；过期数据仅供标记后的展示，`rain_expected` 为未知。空或非法预报不作为无雨证据。
- 无效、非有限或超出 0～100% 的湿度读数不会变成有效零值；缺失摘要在前端显示 `--`。天气不可用、传感器缺失或执行器未知等情况阻止生成启动建议；执行已批准计划前还检查证据与设备状态，降雨风险遵守紧急缺水边界。
- 权限基础数据初始化在同一 SQLAlchemy Session 中只执行一次，避免多项权限依赖反复初始化。角色与权限判断不做全局缓存，新增测试覆盖权限撤销后的拒绝行为。

### 调度接口与页面

- 新增后端及 Next.js 代理 `GET /api/operations`，`section=all|zones|plans`，默认 `all`，非法值返回 422。
- 聚合接口要求 `operations:view`、`assets:view` 和 `dashboard:view`，所有分段使用同一权限集合，不扩展调用者的已有读取权限。未登录返回 401，无权限返回 403。
- 完整响应包含 `zones`、`sensor_summaries`、`active_plans`、`errors`、`timestamp`；分段响应省略未请求的数据组。传感器摘要含分区 ID、指标、有效性与采集时间；无有效读数时指标为 `null`。
- 部分数据读取失败返回 200 与明确的分段错误，失败组不伪装成空列表；全部请求组失败返回 503。单个分区传感器不可用通过摘要状态表达。空分区、无活跃计划与失败分别显示。
- 调度页面只做权限校验，分区和计划在客户端独立请求、独立显示；不再在进入页面前等待完整总览和历史数据。分区每 5 秒、活跃计划每 10 秒刷新，操作成功后刷新相关查询。

### 总览和共享布局

- 总览初始读取和页面轮询不等待天气；天气使用独立的 `/api/weather` 查询，有效数据缓存及轮询周期为 10 分钟，无效数据采用较短的重试周期。天气显示采集时间、过期或不可用状态。
- `/api/dashboard?include_weather=false` 仅省略天气，原接口默认行为保留，其他页面仍可读取完整总览。总览当前仍复用其余聚合数据，没有新增完整后端总览聚合接口。
- 总览与调度迁入 `(console)` 路由组共享布局，URL 仍为 `/` 与 `/operations`。侧栏根据浏览器当前路径更新选中项，两页切换时保留导航并显示加载反馈；其他页面的既有布局保持原入口。
- 总览数据通过 Suspense 展示加载占位，关键文字不再以透明状态开始。图表延迟加载，使用 ECharts core 并只注册折线图、网格、图例、提示与 Canvas 渲染器。
- 后端主应用增加 `Server-Timing` 和 HTTP 耗时日志，天气刷新记录耗时与状态；不记录认证令牌和响应正文。尚未完成所有服务端依赖的逐项关联追踪。

## 2. 生产构建与浏览器实测

使用本机 Next.js 16.2.2 生产构建，前端隔离端口 3301、后端隔离端口 7861；后端使用临时 SQLite 数据库、默认两个分区和实际 API 路由，不启动调度器、不连接真实执行器。没有生成、批准或执行灌溉计划。

浏览器为本机 headless Chrome，通过 CDP 操作导航。桌面视口为 1440×1100，移动视口为 390×844，未主动设置 CPU 或网络限速。先预热两页与图表，再通过侧栏各切换 20 次。调度完成条件为分区和活跃计划结果可见，总览为指标内容可见；采样是自动化脚本的墙钟时间并约每 40 毫秒轮询 DOM，包含一定测试调度开销。

| 场景 | 样本数 | 中位数 | P95（最近秩） | 结论 |
| --- | --- | --- | --- | --- |
| 总览重复切换 | 20 | 631 毫秒 | 638 毫秒 | 此隔离场景满足 ≤ 1 秒目标 |
| 调度重复切换 | 20 | 342 毫秒 | 346 毫秒 | 此隔离场景满足 ≤ 1 秒目标 |

总览样本（毫秒）：`639, 631, 632, 630, 630, 635, 628, 630, 631, 631, 630, 628, 633, 631, 629, 632, 638, 631, 627, 635`。

调度样本（毫秒）：`343, 344, 346, 342, 343, 340, 341, 341, 342, 340, 344, 341, 342, 343, 337, 428, 346, 343, 339, 342`。

同轮首次完整进入调度约 473 毫秒，当时观察到的 LCP 候选时间约 276 毫秒，仅为一次即时观测，不代表完整导航 LCP 分布。历史开发环境 1.8～13.4 秒数据与此次生产隔离测试条件不同，不能计算严格的优化百分比。

桌面、移动两种视口均检查了内容和页面横向溢出，未发现溢出；总览 Canvas 图表可用，容器 opacity 为 1，侧栏选中项随页面更新。浏览器无 JavaScript 异常，业务 API 无失败响应，也没有请求聊天、审计或工具记录接口。浏览器还请求了项目未提供的 favicon，返回 404，此资源不纳入业务 API 成功率。

这次实际 Open-Meteo 请求发生约 10.37 秒超时，返回的天气状态为不可用；主体内容仍然显示，页面切换没有等待它。该现象验证了失败路径的隔离，但没有验证本轮实时天气成功加载。健康接口与慢天气共享同一 ASGI 事件循环的并发隔离另由自动化测试验证。

## 4. 限制与后续验证

- 以上是本机、临时数据的性能结果；当前业务数据量、不同账号、自定义权限、弱网、长期轮询和真实设备环境仍需验收。7 项 ML 相关测试因缺少历史数据初始化辅助脚本而跳过，不代表 ML 路径回归通过。
- 缓存和并发合并为单进程能力，多 worker 部署各有缓存；本轮没有新增 Redis 等共享缓存。
- 共享布局仅覆盖总览与调度，未展开全站布局迁移；其他同步工具入口仍应在后续追踪中检查，不能宣称所有服务端阻塞均已消除。
- 计划的 20 次采样只能作为初步结果，尚无同条件优化前生产基线和完整导航 LCP 分布；保留原目标继续验证。
- 当前天气失败会暂缓启动建议或拒绝证据不足的执行，这是安全约束的落实。上线前须确认天气服务可达，不能通过恢复模拟晴天来换取自动启动成功率。
- 本轮没有重启用户的 3000/7860 服务。应用更新需正常重启后端并重新构建、启动前端，开发服务则通过其正常流程重新加载；启动后复查两个页面和天气状态。回退使用独立提交或定向还原本轮补丁，保留其他工作区修改；无数据库迁移需要回滚。

## 5. 数据大屏后续优化

### 原因和实施

数据大屏原先在服务端串联读取总览、分析和历史，合计 15 个业务 API 调用（另有认证读取）。总览包含天气；分析内部的分区状态、告警列表也会间接触发天气读取或告警评估。页面因而可能等待外部天气网络，而全量历史和完整 ECharts 又增加了传输、解析与首次渲染成本。

本轮已实施：

- `/visualization` 加入 `(console)` 共享布局，进入页面仅校验权限；指标、分析、模型记录由客户端独立加载，不再等待完整总览和历史。
- 新增 `GET /api/visualization?section=summary|models`。指标每 5 秒刷新；分析和模型每 30 秒刷新并复用 React Query 缓存。模型仅返回最近 20 个计划的展示证据字段，不返回完整计划、审批或原始传感器证据。
- 指标接口要求 `dashboard:view` 与 `assets:view`；模型接口要求 `dashboard:view` 与 `operations:view`；最近灌溉时间仅向有 `history:view` 的调用者提供。前端不发起没有模型权限的请求。
- 分析改读传感器摘要及数据库已记录的未解决告警，不在展示读取中触发告警评估。告警列表原入口仍可评估告警；大屏的告警数表示“已记录的未解决告警”，并不保证每次刷新都重新评估天气风险。该变化同样影响复用分析服务的报表页面。
- 湿度趋势先按分区启用的传感器、时间和有效湿度范围筛选，再在 SQL 中按小时或天聚合，避免加载全部历史记录后在 Python 筛选。SQLite 已实测；PostgreSQL/MySQL 的日期函数分支未连接实际数据库验证。
- 图表改为独立动态模块，ECharts core 仅注册折线、柱图、热力图及所需组件。通过 IntersectionObserver 在距视口 160px 内挂载，保留容器高度；指标轮询不重复渲染数据未变的图表组件。
- 缺失湿度保持 `null`，前端显示 `--` 或图表断点；读取失败显示明确提示，已缓存数据保留并标记更新失败。没有恢复模拟天气或更改计划审批、执行规则。
