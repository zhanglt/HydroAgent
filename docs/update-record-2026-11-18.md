# 2026-11-18 更新记录

本记录覆盖本次提交前的全部工作区更新，包括总览、调度、数据大屏的性能优化，以及已有的构建代理与 Next.js 类型入口调整。性能诊断细节见[性能分析](performance-analysis.md)，阶段安排见[优化计划](performance-optimization-plan.md)，实测数据及测试边界见[实施记录](performance-optimization-results.md)。

## 页面与前端

- 总览、调度、大屏迁入 `frontend/src/app/(console)/`，共用布局和加载占位；URL 不变，侧栏根据当前路径更新选中项。
- 总览主数据不等待天气，天气通过独立代理读取；有效天气每 10 分钟刷新，失败或过期状态明确显示。移除主内容最初透明的动画状态。
- 调度将分区与活跃计划拆为独立查询，分别每 5 秒、10 秒刷新；操作成功后失效相关查询，读取失败与无计划分别显示。
- 大屏由原先总览、分析、历史共 15 个业务调用，改为指标、分析、模型三个独立查询。指标每 5 秒，分析与模型每 30 秒刷新。
- 总览图表与大屏图表拆成动态模块，使用按需注册的 ECharts core；大屏屏外图表接近视口后才挂载。模型仅展示最近 20 个计划的预测和决策证据。
- 湿度与缺口类型支持 `null`，在总览、调度、大屏及共用分析组件中保持未知状态，不再把缺失读数显示为有效零值。
- 新增 `/api/operations`、`/api/visualization`、`/api/weather` 的 Next.js 认证代理；总览代理支持 `include_weather=false`，保留默认完整读取行为。
- `frontend/next-env.d.ts` 保留当前 Next.js 开发类型路径 `.next/dev/types/routes.d.ts`；开发和生产构建会更新此生成文件，路由迁移后需重新生成对应类型。

## 后端、权限与安全

- 新增调度读取服务：`section=all|zones|plans`；部分失败返回明确错误信息，全部请求组失败返回 503。三种分段均要求 `operations:view`、`assets:view`、`dashboard:view`。
- 新增大屏读取服务：`section=summary|models`；基础权限为 `dashboard:view`，指标另需 `assets:view`，模型另需 `operations:view`。最近灌溉时间仅向有 `history:view` 的调用者返回。指标计划数在 SQL 中全量计数。
- 分析服务读取独立传感器摘要、执行器及已记录告警，展示读取不触发天气或告警评估；趋势先按传感器和时间筛选，再在数据库按小时/天求平均。报表复用该服务，因此同样使用告警记录快照。
- 传感器展示和天气读取分离；天气有效缓存 600 秒、失败缓存 5 秒，同地点并发请求合并。过期、失败、空预报保留不可用状态，不生成模拟晴天；命中缓存不修改采集时间。
- 同步读取接口使用 FastAPI 线程池；部分异步业务入口预先在线程池查询天气，只传地点字符串。RBAC 基础数据在单个 Session 内只初始化一次，权限本身仍实时检查。
- 启动计划生成和执行前继续检查证据、降雨风险、分区和执行器状态。缺失/非法传感器、过期/不可用天气、禁用/未知/运行中的执行器均不能作为自动启动依据。原有结构化计划、审批、拒绝不可执行及单次执行规则保留。
- 主应用增加 `Server-Timing`、请求耗时日志及天气读取耗时，不记录认证令牌或响应正文。

## 构建与启动脚本现有调整

- `Dockerfile` 的构建、运行阶段 apt 与 pip 命令，以及 `start.sh` 安装后端依赖的命令，使用 HTTP 代理 `http://10.0.0.8:30000`。这些已有本地修改随本次全部更新一并提交，未改写为其他代理方案。
- 该地址是环境相关的内网代理，构建或安装依赖的机器必须能访问它；其他环境需调整命令中的代理地址。`INSTALL_BACKEND_DEPS=never` 可跳过启动脚本的依赖安装，前提是虚拟环境依赖已就绪。
- 未在本轮运行 Docker 镜像构建或通过该代理重新安装全部依赖，不能宣称容器构建已验证通过。
