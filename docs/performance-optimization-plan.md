# 总览与调度页面性能优化计划

编写日期：2026-11-18。状态：P1、P2 已实现，P0、P3 部分完成；本文保留原始设计与验收目标，实际变更、数据和限制见[优化实施记录](performance-optimization-results.md)。优化前证据见[性能分析](performance-analysis.md)。

## 1. 目标与约束

减少两页对慢天气和多余数据的依赖，改善切换反馈，并在生产构建中验证收益。计划最初作为文档交付，当前已实施代码优化；本轮未修改启动脚本或数据库结构，天气异常时增加了暂缓与执行前证据检查。以下保留分阶段工作要求。

默认仅覆盖总览、调度及共享依赖。其他页面做必要兼容性检查，不展开全站重构。保留现有 API 供其他页面使用，不做数据库迁移，不修改审批执行接口契约。

灌溉仍须按分区生成结构化计划，包含证据、安全审查、建议时长和风险等级。启动必须有明确批准，除非使用在同一事务创建并批准计划的手动覆盖入口；批准记录保留操作者、时间与可选说明。拒绝计划不可执行，批准计划只允许执行一次。中高风险启动计划继续请求审批。

天气强烈提示未来 48 小时降雨时，非紧急缺水不应启动；传感器缺失或无效时生成暂缓计划并记录审计；执行器未知、禁用或运行中时避免自动执行。性能优化不得绕过这些规则。

## 2. 分阶段实施

| 阶段 | 状态 | 实施内容 | 完成条件 |
| --- | --- | --- | --- |
| P0 基线 | 部分完成 | 已保留优化前观测，并增加 HTTP 与天气计时；尚无同环境优化前生产分布与完整依赖追踪 | 有可复现基线和浏览器轨迹，能区分网络、服务端等待与绘制 |
| P1 数据链路 | 已实现并测试 | 传感器与天气拆分、线程隔离、独立缓存、并发合并及调度专用取数 | 传感器展示不访问天气，调度不拉完整历史，慢天气不阻塞独立健康接口 |
| P2 页面反馈 | 已实现并验证 | 两页共享布局、加载占位、分段查询、独立轮询、图表按需加载和首屏可见 | 切换有即时反馈，慢区域不拖住其他内容，无额外业务数据请求 |
| P3 验证交付 | 部分完成 | 已完成隔离生产构建与浏览器采样；真实业务数据、完整导航 LCP 分布及长期运行尚待验证 | 给出实测分布、目标达成情况、剩余瓶颈和回退方式 |

### P0：建立基线和计时

- 对路由取数、后端依赖、天气请求分别记录耗时、结果、缓存命中和关联标识，不记录令牌、密钥或完整敏感响应。记录总耗时与独立依赖耗时，避免将并行请求相加。
- 浏览器分别录制完整导航和客户端路由切换，标注点击、加载反馈、关键内容可见时间；记录预取、路由缓存、CPU 与网络限速设置。总览关键内容为顶部指标，调度关键内容为分区状态与活跃计划结果。
- 在相同账号、分区数据、视口和负载条件下采样。总览与调度均测首次加载、首次切换和重复切换；重复切换每种场景至少 20 次。报告中位数、P95、错误数及样本数，首次加载与重复切换分开。

### P1：拆分读取并限制天气影响

- 提取独立的传感器摘要读取能力，供当前传感器接口及展示聚合使用；不调用完整 `get_zone_status()` 收集天气、设置和计划。天气展示也直接读取天气，不反向读取传感器。计划生成保留完整证据收集链路。
- 在异步调用入口将同步天气网络请求及其异常处理放到工作线程，保留既有网络超时；只在线程间传递地点、天气结果等普通数据。SQLAlchemy Session、ORM 对象和事务不跨线程共享，不能把整个灌溉服务函数直接放进共享线程。
- 传感器缓存保留 5 秒，天气有效期默认 600 秒，使用独立常量；所有天气调用入口使用同一缓存策略，避免只修页面路径。按地点合并正在进行的刷新，失败时释放等待者并清理任务状态，允许后续重试。此阶段采用单进程缓存，不新增分布式缓存依赖。
- 天气结果保留真实采集时间、来源和有效性；缓存命中不重置采集时间。过期天气可用于明确标为过期的展示，刷新失败不得将模拟晴天或未知状态用于自动启动判断；首次无数据时展示不可用。计划生成及执行按安全校验要求处理过期或失败证据，无法确认安全时暂缓或要求人工处理。
- 新增调度专用读取能力，聚合分区、传感器摘要和活跃计划；避免查询会话、工具调用、审计、历史决策及总览中的无关数据。活跃计划继续采用待审批、已批准、执行中的现有状态规则。

### P2：页面、缓存与轮询

- 将共享侧栏放入受保护页面的公共布局，登录页保留独立布局；侧栏根据当前路由更新选中项。各页面保留自身权限校验，不能仅依赖缓存布局授权，也不能将用户数据放入跨用户共享缓存。
- 增加路由加载占位，并让分区状态、活跃计划、天气和图表独立展示加载或错误状态。未知值显示缺失或不可用，不使用 `0%` 代替缺失湿度；空列表与读取失败分开表达。
- 调度使用独立查询键，不复用完整 `dashboard`、`history` 载荷。分区状态每 5 秒刷新、活跃计划每 10 秒刷新；审批、拒绝、执行和计划生成成功后刷新相关查询。可使用专用接口的分段参数达到不同刷新频率，避免每次拉取全部内容。
- 总览保留必要指标刷新，天气刷新与 600 秒缓存周期配合；标题、说明和关键指标默认可见，不依赖 `opacity: 0` 入场动画。保留不阻塞关键内容的局部动画。
- 图表改用 ECharts core，显式注册实际使用的图表、组件及渲染器，并延迟加载图表区域。以生产实际加载与传输量验证收益，不以开发目录大小推算。

### P3：发布验证和观测

- 在隔离端口运行生产构建，不停止当前开发或业务服务。按同一测试方案重测，记录构建版本、环境、样本和异常；模拟慢天气在测试环境完成。
- 分别提交后端读取优化、调度迁移和前端展示调整，保持现有入口可用。若出现回归，按对应提交回退；缓存为进程内数据，回退后重新建立，不需数据库回滚。
- 将后续结果追加为实际验证记录，保留本文原始目标。未达标时报告真实数值、失败场景和剩余成本，不以“增加了加载动画”代替内容完成时间改善。

## 3. 接口和类型调整

以下接口已实现；最终契约及与原始设计的差异见实施记录。

| 接口或类型 | 计划契约 |
| --- | --- |
| 后端 `GET /api/operations` | 要求 `operations:view`，复用现有分区和计划读取权限约束；不因聚合接口放宽调用者权限 |
| 查询参数 `section` | `all` 为默认，返回完整调度展示数据；`zones` 只读取分区与传感器；`plans` 只读取活跃计划；非法值返回 422 |
| Next.js `GET /api/operations` | 转发登录态与 `section`，保留后端权限错误；服务端初始加载可直接调用后端同一能力 |
| 前端调度数据类型 | 新增 `OperationsData` 及分段响应类型，复用现有 `Zone`、`IrrigationPlan`；增加每分区传感器摘要及其有效性、采集时间和分段错误信息 |
| 天气摘要 | 新增采集时间、来源与有效性元数据；保留现有字段供调用者兼容，新字段同步反映到前端展示类型 |

完整调度响应按 `zones`、`sensor_summaries`、`active_plans`、`errors` 分组。传感器摘要以 `zone_id` 关联，包含 `average`、`status` 和 `collected_at`；无有效读数时指标为 `null`，不填零。分段响应只提供请求的组及其错误信息。分区或计划读取失败不得返回表示成功的空数组：全部不可用返回 503；部分可用返回 200 并明确标识失败区域。认证与权限错误保持 401/403，不转换为普通区域错误。

新响应只服务展示，不构成审批或执行凭证。现有计划生成、批准、拒绝和执行 API 继续负责事务和安全检查；新接口不触发计划生成或执行副作用。

## 4. 测试与验收

### 功能与安全回归

- 覆盖两个分区的有效、缺失、非法和部分失败读数，验证缺失状态不变成零湿度；传感器缺失时计划暂缓并保留审计记录。
- 覆盖天气正常、慢响应、请求失败、缓存有效与过期、首次无缓存、同地点并发刷新；确认时间不因命中重置，失败任务不永久占用合并状态。
- 用慢天气模拟验证 `/api/health` 等独立请求仍可及时返回；检查传感器展示的外部天气调用次数为零，同地点并发天气查询在单进程中只发起一次刷新。
- 覆盖调度 `all/zones/plans`、空分区、无活跃计划、部分区域失败、401/403 和非法参数；检查没有读取会话、审计、工具调用等无关数据。
- 使用测试数据库与模拟执行器验证批准、拒绝、单次执行、执行器未知或运行中、降雨风险和证据过期，确保保留显式批准与安全约束。真实环境性能采样不生成、审批或执行灌溉计划。
- 检查登录、退出、权限不同的账号切换、侧栏高亮、桌面和移动视口，以及总览、调度、审计等现有页面兼容性。

### 检查命令

代码实施后执行仓库现有前端检查及相关后端测试；本轮已执行的检查、跳过与失败项见实施记录。全量测试中的 `test_main_run` 会直接启动服务器，不能当作无副作用的检查使用。

```bash
# 在 frontend/ 中运行
npm run typecheck
npm run lint
npm run build

# 在仓库根目录运行
.venv/bin/python -m unittest discover -s tests
```

为缓存、并发、权限与安全行为增加有意义的测试。测试使用隔离数据及模拟外部天气，避免自动化测试依赖真实天气响应；真实天气只作为单独标明的联网验证。

### 性能目标和结果口径

| 项目 | 建议验收目标 | 验证方式 |
| --- | --- | --- |
| 生产环境重复切换 | 点击到关键内容可见 P95 ≤ 1 秒 | 固定环境、每场景至少 20 次；缓存与错误状态单列 |
| 完整页面导航 | LCP ≤ 2.5 秒 | 生产构建，固定设备和网络；不与客户端切换混算 |
| 慢天气隔离 | 注入慢天气时独立健康接口 P95 ≤ 200 毫秒 | 同机隔离环境，无额外限速；记录基线与实际分布 |
| 调度数据依赖 | 不请求完整历史与完整总览 | 浏览器网络和后端调用记录双重检查 |
| 传感器展示 | 不触发外部天气请求 | 测试调用计数与运行追踪 |
| 首屏图表成本 | 关键文字先于图表加载可见，依赖按需加载 | Performance 与生产资源清单 |

以上均为待验证目标，不是已实现承诺；生产测量前不能宣称达标。P95 使用升序样本的最近秩方法，至少 20 次采样作为起点；异常请求不得从统计中静默删除。降级展示的及时性与新鲜数据成功率分别报告。
